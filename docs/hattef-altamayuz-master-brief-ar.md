> هذا الملف يجمع المشروع كاملًا في مكان واحد: الفكرة، الهوية، الفروع، الصفحات، دورة الصيانة، الحسابات، الفواتير، الإشعارات، الجوائز، التقارير، الأمان، وما وصل إليه النظام في آخر تحديث. وفي القسم الأخير يوجد **أمر رئيسي واحد جاهز للنسخ** يمكن إرساله مستقبلًا لبناء نظام مماثل بالمواصفات نفسها.

## 2. الهوية والتصميم وتجربة الاستخدام

الواجهة مبنية بأسلوب سماوي وأبيض مع بطاقات زجاجية شفافة قليلًا، وخلفية هوية متحركة مع التمرير تحتوي رسوم أجهزة وجوالات وكمبيوترات وتروس ومفكات وبراغي وبرمجة. جميع المربعات البيضاء شفافة بدرجة محسوبة حتى تظهر الخلفية دون أن تضعف قراءة النص.

تعمل الصفحات باتجاه RTL، ومتجاوبة مع iPhone وiPad والكمبيوتر. أزرار اللمس كبيرة، وخاصة قائمة تغيير حالة الجهاز على iPhone. لا يظهر للعميل أي دخول داخلي أو اسم للمنصة التي بُني بها الموقع، ولا توجد هوية خارجية في الواجهات العامة.

العبارة الترحيبية الأساسية هي: **«يا بعد القصيم كله… نورتناااا 🩵 تطمن… جهازك جهازنا 📱 كل تحديث على جهازك يوصلك أول بأول… بدون ما تحتاج تسأل أحد»**. وتظهر مرة واحدة على الجهاز بدل التكرار في كل زيارة. والعبارة السفلية هي: **«رحلة جهازك واضحة… من أول دقيقة إلى لحظة التسليم. 🩵»**، مع إبراز أن المحل خدم أكثر من سبعة آلاف جهاز صيانة بنجاح ومستمر.

## 4. دورة الطلب والفاتورة

يدعم النظام خدمتي الصيانة والبرمجة. لكل طلب رقم فاتورة متسلسل ورمز تتبع آمن، ويرتبط بفرع واحد وعميل واحد عند توفر رقم الجوال. تتضمن بيانات الاستلام: الجهاز، الماركة، الموديل، الرقم التسلسلي، العطل المبلغ عنه، الملحقات المستلمة، حالة الجهاز، صور قبل الصيانة، السعر، التكلفة الداخلية، المدفوع، الموعد المتوقع، مدة الضمان، الملاحظات الظاهرة للعميل، الملاحظات الداخلية، ومكان الجهاز داخل المحل.

| الحالة | معناها للعميل والإدارة |
|---|---|
| تم الاستلام | الجهاز وصل للمحل وينتظر بدء العمل |
| قيد الفحص | الفني يشخّص الجهاز والعطل |
| بانتظار الموافقة | السعر أو عطل إضافي ينتظر قبول العميل أو رفضه |
| جاري العمل | بدأت الصيانة أو البرمجة |
| جاهز للاستلام | انتهى العمل والجهاز بانتظار العميل |
| تم التسليم | استلم العميل الجهاز وبدأت دورة الضمان |
| ملغي | أُلغي الطلب مع بقاء السجل محفوظًا |

يمكن إرسال موافقة سعر عند إنشاء الطلب، كما يمكن إرسال عطل إضافي لاحقًا مع تكلفة جديدة؛ يوافق العميل أو يرفض من رابط التتبع، ويُحفظ الرد والوقت في السجل. عند تغيير الحالة تُسجل هوية الفاعل والفرع والوقت والملاحظة.

### الفاتورة المطبوعة

الفاتورة الآن مصممة لتُطبع **كاملة في ورقة A4 واحدة فقط**. تحتوي على شعار هاتف التميز، رقم الطلب، بيانات العميل والجهاز والخدمة، الحالة، الإجمالي والمدفوع والمتبقي، الضمان، معلومات الفرع، QR، وباركود CODE128. يظهر شعار المحل فوق قسم QR والباركود، وتبقى كتلة التتبع في الصفحة نفسها دون انقسام. يوجد زر الطباعة داخل تعديلات الفاتورة في لوحة المالك.

## 5. حسابات العملاء والبحث بالهاتف

عند إنشاء أول فاتورة برقم جوال، ينشئ النظام حساب عميل تلقائيًا بكلمة مرور عشوائية، ويربط أي فاتورة مستقبلية تحمل الرقم نفسه بالحساب نفسه. يستطيع العميل الدخول لرؤية فواتيره فقط، ولا يستطيع رؤية فاتورة عميل آخر أو بيانات فرع لا تخص طلباته.

أضيفت في لوحة المالك خانة **«ابحث عن عميل برقم الجوال»**. يعرض البحث، داخل الفرع المفتوح فقط، اسم العميل ورقمه، جميع فواتيره، حالة كل فاتورة، الجهاز، نوع الخدمة، السعر، تواريخ التسليم، وحالة الضمان. تُميّز الفواتير التي لم تُسلّم بعد، ويمكن اختيار واحدة منها وإرسال Popup لها وحدها. لا تظهر الرسالة في الفواتير الأخرى للعميل نفسه.

## 6. المالك والفروع

دخول المالك مخفي عن العميل ويصل إليه عبر رابط داخلي خاص. بعد كلمة مرور المالك تظهر شاشة اختيار الفرع؛ يختار البساتين أو البصيرية، ثم يدخل كلمة حماية الفرع. جلسة الفرع قصيرة، منفصلة، وموقعة. لوحة كل فرع معزولة عن الأخرى في الطلبات والعملاء والموظفين والتقارير والتقييمات والرسائل والإعدادات.

تتضمن لوحة المالك:

| المجال | الوظائف |
|---|---|
| الطلبات | إنشاء وتعديل وأرشفة واستعادة وحذف آمن وتغيير الحالة والطباعة والصور |
| العملاء | البحث بالجوال، الحساب، كل الفواتير، الضمانات، الأوسمة، والرسائل الخاصة |
| المالية | المبيعات والتكلفة والربح والمتبقي ومتوسط الفاتورة، مع فتح محمي بكلمة مرور |
| الإحصاءات | الطلبات النشطة، الجاهز، بانتظار الموافقة، أجهزة الصيانة المنجزة، الزوار، المتصلون الآن، الحسابات، أكثر الأعطال، سرعة الإنجاز، ومتوسط الانتظار |
| التنبيهات الداخلية | القطع الناقصة والتنبيهات المهمة والحالات والأولوية والأرشيف وسلة محذوفات قابلة للاستعادة |
| المحتوى | تعديل نصوص الموقع وعبارات Popup والرسائل العشوائية من قاعدة البيانات |
| التقارير | تصدير الفواتير والتقارير المالية إلى Excel وWord |
| الفروع | بيانات الفرع والواتساب والخريطة وساعات العمل وكلمة الحماية |
| الموظفون | إنشاء الحساب والصلاحيات والفرع وكلمة المرور والحذف الآمن والنقل بين الفروع |

## 7. الموظفون والصلاحيات

تظهر في بوابة الإدارة خانتان واضحتان: **مالك** أو **موظف**. يدخل الموظف باسم المستخدم وكلمة المرور التي يتحكم بها المالك. يرى اسم الفرع الذي عُيّن فيه والصلاحيات الممنوحة له بالعربية، ولا يستطيع تبديل الفرع من حسابه.

يمكن للمالك نقل الموظف من البساتين إلى البصيرية أو العكس. عند النقل يتغير الفرع الأساسي ويزداد إصدار الجلسة، فتُبطل الجلسة القديمة ويضطر الموظف للدخول من جديد. يظهر الفرع الحالي بجانب اسم الموظف، ويُسجل النقل في سجل التدقيق.

الصلاحيات دقيقة وليست مجرد إخفاء أزرار. يتحقق الخادم منها قبل كل عملية، وتشمل على سبيل المثال: عرض طلبات الفرع، إنشاء الفواتير، إنشاء العملاء، تحديث الاستلام، رفع الصور، مشاهدة الصور، وتغيير الحالة إذا سمح المالك. كلمة الموظف المبدئية `12Qwaszx*` محفوظة مجزأة، وتصبح الكلمة التي يعينها المالك دائمة حتى يغيرها لاحقًا.

## 8. الرسائل المنبثقة والإشعارات

يوجد نوعان متكاملان من التواصل داخل النظام. الأول Popup داخل الموقع، والثاني Web Push يصل خارج الموقع بعد موافقة العميل على الإشعارات.

| الحدث | Popup | Web Push |
|---|---:|---:|
| رسالة خاصة من المالك لفاتورة | نعم | نعم |
| تغيير حالة الجهاز | بحسب الإعداد | نعم |
| جاهز للاستلام | نعم | نعم |
| تم التسليم | مرة واحدة | نعم |
| طلب موافقة سعر | نعم | نعم |
| عطل إضافي وتكلفة | نعم | نعم |

تُرسل الرسالة الخاصة إلى **فاتورة محددة** يختارها المالك، وتحمل معرّف الطلب والعميل والفرع. تسجّل مشاهدة الرسالة في الخادم، لذلك لا تعود بعد عرضها أو إغلاقها، ولا تظهر في فاتورة ثانية حتى لو كانت للعميل نفسه.

إذا أصبحت الفاتورة «تم التسليم»، يحجز الخادم نافذة ما بعد التسليم ذريًا لتظهر مرة واحدة فقط لأول دخول، حتى لو فتح العميل الرابط من جهازين متزامنين. النص الودي هو: **«بشّر، كل شيء على ما تحب؟ 🩵»**، مع واتساب الفرع المناسب إذا لم يكن العميل راضيًا.

## 9. مكتبة العبارات العشوائية

العبارات محفوظة في قاعدة البيانات وقابلة للتعديل والتعطيل وتحديد الفرع والوزن. الاختيار عشوائي وغير متسلسل. تشمل الفئات: أثناء الصيانة، صار جاهز، قبل التقييم، بعد التسليم، قبل الكشط، الفوز، والخسارة.

أمثلة أثناء الصيانة: «دخلنا معه في جلسة مصارحة»، «الجهاز للحين يسوي نفسه ما فيه شيء»، «الجهاز عنيد شوي… بس حنا أعند»، «إذا الجهاز تكلم… بنبلغك»، و«لاتخاف ترا ما خليناه ريموت». وأمثلة الجاهزية: «يلا تعال… خلصنا سواليف معه»، «ترى صار يسأل: وين راعيي؟»، و«تعال قبل نخليه موظف عندنا». وأمثلة ما بعد التسليم: «نبي نشوفك… بس بدون جهاز خربان»، و«إذا الجهاز صار مؤدب… ترى من تربيتنا».

## 10. اكشط واربح والتقييمات

ينشئ المالك حملة لكل فرع ويولد 100 كود دفعة واحدة، ويحدد الجوائز وأعدادها مثل ستيكر أو تنظيف أو خصم أو جائزة مخصصة. الكود يستخدم مرة واحدة، ويرتبط بالفاتورة، وتبدأ صلاحيته لمدة 72 ساعة وفق دورة التسليم. يدير المالك عبارات ما قبل الكشط والفوز والخسارة من اللوحة.

بعد التسليم يظهر التقييم. إذا اختار العميل خمس نجوم يُوجّه إلى خريطة Google للفرع. إذا كان التقييم أقل من خمس نجوم يكتب ملاحظته وتصل إلى لوحة المالك، ولا تُنشأ أي تقييمات أو مراجعات مختلقة داخل النظام.

## 11. واتساب

النظام مجهز معماريًا لـ**WhatsApp Cloud API الرسمي** متعدد الفروع، مع قوالب إنشاء الحساب والفاتورة وتغيير الحالة والجاهزية والتسليم والضمان والفوز. الإرسال الفعلي ما زال معطلًا عمدًا حتى يوفر المالك بيانات Meta الرسمية لكل فرع. توجد روابط واتساب يدوية وقائمة رسائل معلقة إلى حين التفعيل. لا يُستخدم ربط غير رسمي ولا محاكاة إرسال حقيقي.

## 12. الأمان والاستمرارية

طبّقت حماية متعددة الطبقات بدل الاعتماد على الواجهة وحدها. كلمات المرور مجزأة ومملحة، والجلسات موقعة وتُخزن في Cookies تحمل Secure وHttpOnly وSameSite. تغيير كلمة الموظف أو نقله أو حذفه يرفع إصدار الجلسة ويبطل الجلسات القديمة.

| الحماية | التنفيذ |
|---|---|
| عزل الفروع | رقم الفرع الموثوق يأتي من الجلسة، وليس من إدخال الواجهة |
| الصلاحيات | وسائط خادم مركزية للمالك والفرع والموظف والعميل |
| IDOR | التحقق من ملكية الطلب والعميل والصورة والرسالة قبل القراءة أو التعديل |
| CSRF | فحص Origin/Host للطلبات المغيّرة للحالة |
| Rate Limiting | حدود عامة وحدود أشد للدخول والتتبع والرسائل والرفع |
| XSS | لا يوجد عرض HTML خام من المستخدم، مع CSP صارمة |
| SQL Injection | استعلامات Drizzle معلّمة ولا تُدمج المدخلات في SQL نصي |
| رفع الصور | حد للحجم، نوع MIME، فحص بصمة الملف، وصلاحية الطلب والفرع |
| الرؤوس | HSTS وCSP وframe-ancestors وnosniff وReferrer-Policy وPermissions-Policy |
| النسخ الاحتياطي | تشفير AES-256-GCM |
| سجل التدقيق | تحقق HMAC وتسجيل الفاعل والفرع والوقت |
| التخزين | تخزين ملفات سحابي دائم، وعدم الاعتماد على ملفات السيرفر المحلية |

تُطبّق جميع الهجرات بصورة غير مفقِدة للبيانات، ولا تُحذف الطلبات أو العملاء حذفًا نهائيًا من الواجهة. قبل كل نشر يجب تشغيل فحص TypeScript وجميع اختبارات Vitest وبناء الإنتاج، ثم فحص الجوال والكمبيوتر والطباعة.

## 14. ما يجب تذكره عند صيانة المشروع

لا تُكتب بيانات الفروع أو الرسائل أو الجوائز أو الخرائط داخل مكونات الواجهة إذا كانت قابلة للتغيير؛ يجب حفظها في الإعدادات أو قاعدة البيانات. لا تُنشأ مراجعات أو تقييمات أو أرقام نجاح وهمية على أنها آراء حقيقية. لا يُكشف سعر التكلفة أو مكان الجهاز أو الملاحظات الداخلية للعميل. لا يُغيّر شعار حقوق وليد عند تعديل شعار المتجر. لا يُنفذ حذف مدمر أو هجرة مفقِدة للبيانات.
